# 교육장 추론 서비스 v1 — 결과 형식 문서

team2-2 서비스는 실습실·회의실·사무실의 60분 예측, 이상 여부, 사용 여부·환기 경보를 매분 MQTT와 조회 API로 내보낸다. 이 문서만 보고 가져다 쓸 수 있다.

## 접속

| 어디서 접속하나 | MQTT | 조회 API |
|---|---|---|
| **교육장 같은 Wi-Fi** (다른 팀 기본) | `172.27.91.139:1884` | `http://172.27.91.139:8090` |
| Tailscale(team2-2 초대를 받은 경우) | `100.92.224.43:1884` | `http://100.92.224.43:8090` |

인증: MQTT 읽기와 API는 인증이 없다. MQTT 쓰기는 서비스 계정만 할 수 있다. 두 주소는 2026-10-21 Mac에서, Wi-Fi 주소는 다른 노트북에서도 문서만 보고 접속을 확인했다.

**교육장 Wi-Fi 주소가 바뀌었을 때**: `172.27.91.139`는 공유기가 나눠 준 주소라서, 보드를 재부팅하거나 Wi-Fi에 다시 붙으면 바뀔 수 있다. 접속이 안 되면 보드 터미널에서 지금 주소를 확인하거나 team2-2에 물어본다.

```bash
ip -4 -o addr show wlP1p1s0 | awk '{print $4}'   # 예: 172.27.91.139/14 → 주소는 / 앞부분
hostname -I                                       # 첫 번째 172.27.… 가 Wi-Fi 주소
```

접속 확인: `curl http://172.27.91.139:8090/health`의 응답에 `"failures": 0`이 들어 있으면 연결된 것이다. 교육장 밖(다른 네트워크)에서는 이 주소로 닿지 않는다.

## MQTT 토픽

| 토픽 | 내용 | retain | 주기 |
|---|---|---|---|
| `team2-2/inference/lab` · `/meeting` · `/office` | 공간별 전체 결과(아래 JSON) | ✅ 새로 구독해도 최신값을 바로 받는다 | 매분 (xx:xx:05) |
| `team2-2/inference/<공간>/alert` | 알림 대상 경보 한 건씩 | ❌ | 경보가 처음 생길 때, 그리고 계속되면 30분마다 |
| `team2-2/inference/_status` | 서비스 상태(주기 수, 실패 수, 처리 시간) | ✅ | 매분 |

```bash
mosquitto_sub -h 172.27.91.139 -p 1884 -t 'team2-2/inference/#' -v
```

## 조회 API

| 요청 | 답 |
|---|---|
| `GET /health` | 서비스 상태 `{started, cycles, failures, last_cycle, last_error, last_elapsed_s}` |
| `GET /spaces` | 공간별 요약 `{lab: {space, time, now, alerts}, …}` |
| `GET /spaces/{lab\|meeting\|office 또는 실습실\|회의실\|사무실}` | 공간 전체 결과(아래 JSON) |
| `GET /spaces/{공간}/co2?minutes=30` | "N분 뒤 CO₂는?" `{space, base_time, minutes_ahead, co2_ppm, temperature_c, co2_over_1000_in_min}` (5분 단위로 반올림, 5~60분) |
| `GET /spaces/{공간}/accuracy` | 서비스가 스스로 채점한 예측 오차. 최근 6시간 60분 앞 CO₂ MAE `mae_co2_60_ppm`, 채점 건수 `n_60`, 경보 기준 `threshold_co2_60_ppm`, 기준 초과 여부 `degraded`, 5~60분 앞별 오차 `by_horizon[]` |

```bash
curl 'http://172.27.91.139:8090/spaces/meeting/co2?minutes=30'
```

## 결과 JSON (공간 하나)

| 필드 | 단위 | 뜻 |
|---|---|---|
| `space`, `topic_space` | — | 공간 이름(한글), 토픽용 이름 |
| `time` | KST ISO | 계산 기준 시각. **끝난 5분 칸의 끝**이다. 막 시작된 칸은 쓰지 않는다 |
| `computed_at` | KST ISO | 실제 계산 시각 |
| `model_version` | — | `v1` |
| `data.last_message_kst`, `data.minutes_since_last` | KST, 분 | 마지막 센서 수신 시각과 경과 시간 |
| `data.devices` | — | 이 공간에서 값을 낸 센서 목록. 여러 대면 센서별로 5분 값을 정리한 뒤 평균으로 합친다 |
| `now.co2_ppm`, `now.temperature_c`, `now.humidity_pct` | ppm, ℃, % | 기준 시각의 값(정제 후) |
| `forecast[]` | — | 5분 간격 12개 `{minutes_ahead, time, co2_ppm, temperature_c}`. 최근 4시간 데이터가 절반 미만이면 `null` |
| `co2_over_1000_in_min` | 분 | 1,000ppm을 처음 넘을 것으로 예측한 시점. 이미 넘었으면 0, 넘지 않으면 `null` |
| `anomaly.score`, `anomaly.threshold`, `anomaly.is_anomaly` | — | 오토인코더 재구성 오차와 경보 기준. 데이터가 끊기거나 최근 15분에 빠진 값이 있으면 `null` |
| `anomaly.culprit_sensor`, `anomaly.per_sensor` | — | 오차가 가장 큰 항목(co2/temperature/humidity)과 항목별 오차 |
| `state.occupied`, `state.occupied_prob` | bool, 0~1 | 센서만으로 추정한 사용 여부 |
| `state.ventilation_warning`, `state.ventilation_prob` | bool, 0~1 | 30분 안에 1,000ppm을 넘을 가능성(지금 1,000 미만일 때만 경보) |
| `hvac_power` | bool | 냉난방 실내기 전원(xflow). 연결된 실내기가 없으면 `null` |
| `accuracy` | ppm | 서비스가 지난 예측을 실제 값과 비교해 낸 최근 6시간 오차 요약(`/accuracy`와 같은 내용). 실제 값이 들어오지 않은 초기에는 건수가 적다 |
| `alerts[]` | — | 지금 켜져 있는 경보 `{type, severity, sensor, message, notify, since}` |
| `resolved[]` | — | 이번 주기에 꺼진 경보 `{type, status:"resolved", at}` |

### 경보 종류 (`alerts[].type`)

| type | 조건 | severity |
|---|---|---|
| `data_gap` | 센서 메시지가 끊김(실습실·사무실 5분, 회의실 90분 넘게. 센서 주기에 맞춤) | warning |
| `stuck` | 한 센서의 값이 60분 동안 전혀 바뀌지 않음 | warning |
| `out_of_range` | 최근 10분에 물리적으로 불가능한 값(정제에서 제외됨) | info |
| `anomaly` | 오토인코더 점수가 기준 초과 | warning |
| `co2_high` | 지금 1,000ppm 이상 | warning |
| `co2_forecast` | 60분 안에 1,000ppm 초과 예측 | info |
| `ventilation_soon` | 분류기가 30분 안 초과 가능성 높다고 판단 | info |
| `hvac_empty_room` | 빈 방으로 추정되는데 냉난방이 켜짐 | info |
| `forecast_degraded` | 최근 6시간 60분 앞 CO₂ 예측 오차가 기준(검증 오차의 2배, 68.6ppm)을 넘음(채점 12건 이상일 때) | warning |
| `compute_error` | 이 공간 계산이 실패함. 다음 주기에 다시 시도한다 | warning |

**알림 규칙**: 같은 경보를 매분 보내면 운영자가 알림을 꺼 버린다. 그래서 `notify=true`는 경보가 처음 생길 때와 계속되는 동안 30분마다만 붙는다. 경보가 사라지면 `resolved`에 한 번 나온다.

## LLM 에이전트·대시보드가 쓸 때

- 질문 "회의실 30분 뒤 CO₂는?" → `GET /spaces/meeting/co2?minutes=30`
- 답할 때 함께 확인할 것은 세 가지다. `data.minutes_since_last`로 데이터가 최신인지, `forecast`가 `null`이 아닌지, 기준 시각 `time`이다.
- 두 신호가 다를 수 있다. 예측은 '20분 뒤 초과'인데 분류기는 '경보 아님'일 수 있다. 환기 판단은 `ventilation_warning`(재현율 우선 분류기)을, '몇 분 뒤'는 `co2_over_1000_in_min`을 쓴다.
- 오차 참고: 서비스 예측 모델의 60분 뒤 CO₂ MAE는 합성 시험 28.6ppm, 온도 0.34℃다. 실데이터에서는 더 클 수 있다([실데이터 재평가](../report/real_data.md)).
- 회의실 센서는 약 30분마다 보내서 `forecast`가 자주 `null`이다.
